# Widget flotante de pendientes — Grupo CESA

Windows Electron widget. The full plan is in `docs/PLAN.md`; `README.md` explains how to run it; `docs/MANUAL_TESTS.md` lists the checks that need a human.

Stack: Electron, electron-vite, React 19, Tailwind v4 (tokens in `src/renderer/assets/main.css`), Zustand, zod, Vitest, `node:sqlite` + Drizzle, safeStorage for secrets. Commands: `npm run dev`, `npm test`, `npm run lint`, `npm run typecheck`, `npm run build`.

## Decisions to keep
- Read-only integrations (ClickUp, Google Calendar/Gmail, Slack). ClickUp client exposes only GET.
- Phase 8 (daily summary) is authorized and in progress. The AI is Gemini with the user's own key (stored in `secrets.bin`, never in settings, logs or the repo), and it is used ONLY to write the daily summary. It works without AI (rules summary is the fallback), sends the minimum by default (meeting + ClickUp titles; mail, distribution lists and Slack only as counts unless the user raises that source's level: `ai.mail`, `ai.lists`, `ai.slack` = `counts` | `titles` | `people`, the last adding who wrote it; older `sendMail`/`sendSlack` switches are migrated in `migrateLegacy`). The summary has sections `mail` (latest 3 unread individual mails) and `lists` (grouped per list in code), a note under an AI summary says which source it could not read (`Briefing.notices`), and `ai.extras` only change the style (they add no data), masks sensitive text, and records every request in `ai_audit_log`. Gemini model names change often: check docs before changing the default in `settingsSchema.ts`.
- Work phase by phase; the user authorizes each one.
- Installer and updates (done): per-user NSIS installer (`electron-builder.yml`), auto-update with `electron-updater` from GitHub Releases of the separate public repo `LusioG/Widget-GrupoCESA-releases`. `npm run release` publishes (needs `GH_TOKEN`). NEVER change `appId` (`com.grupocesa.widget`, must equal `setAppUserModelId`): a different id is a different app and updates stop replacing it. userData is pinned to `%APPDATA%\widget` in `main/index.ts`. The `files` list must keep `'**/*'` first and the migrations include last (the installed app reads `src/main/db/migrations`); `tests/packaging.test.ts` guards this. The installer is unsigned (SmartScreen warns once).
- Never commit or log secrets. Credentials live encrypted in `%APPDATA%\widget\secrets.bin`; logs in `%APPDATA%\widget\logs`.
- Tests must NEVER delete `%APPDATA%\widget` or kill every electron process: use an isolated `--user-data-dir` and kill by PID.
- The content of "Fuentes y filtros" (formerly "Qué vigilar") is not to be removed.
- UI text is in Spanish and lives in `src/shared/strings.ts`. Accessibility rules: text >= 12px, targets >= 24px, visible focus, respect reduced motion.
- Slack: polled every 60 s while up to ~10 people use the widget (the limit is shared, see `accounts.ts`: raise it for more people; Calendar and Gmail every 30 s, ClickUp every 60 s; see `accounts.ts` for why: the Slack limit, `search.messages` Tier 2 = "20+"/min per workspace AND app, is shared by every person because they all use the one app; each check makes 2 searches; the others are per person) with ONLY the user token (`xoxp-`, scopes `search:read`, `channels:read`, `groups:read`, `im:read`, `mpim:read`, `users:read`), using `search.messages` (`is:dm` and `<@me>`). No Socket Mode and no `xapp-` token (removed). Sign-in with the COMPANY's one Slack app (built, waiting for its Client ID): the free workspace allows only 10 apps and all 10 are taken, so the admin made the user a collaborator of an EXISTING app (a bot's) to reuse it. `SLACK_CLIENT_ID` in `src/shared/slackApp.ts` is empty until it is known (or env `SLACK_CLIENT_ID`); while empty the card keeps asking for a token by hand. With it set, "Conectar con Slack" runs OAuth with PKCE (`main/auth/slackOAuth.ts` pure, `slackSignIn.ts` Electron): system browser to slack.com/oauth/v2/authorize with `user_scope`, redirect to `grupocesa-widget://slack`, Windows gives the address to the running widget through `second-instance` (the scheme is registered by the installer, `protocols` in `electron-builder.yml`, and by the app when packaged; in development only with `WIDGET_REGISTER_PROTOCOL=1`, because the scheme belongs to ONE program), code swapped at `oauth.v2.access` with the verifier and NO client secret (a test forbids the word). Tokens that expire (`xoxe.xoxp-`) are renewed with the refresh token a few minutes before; if Slack refuses (30 days unused) the account asks to reconnect. PKCE is IRREVERSIBLE for that app (public client, only Slack support can undo it) and applies to the whole app, bot included: NEVER paste `docs/slack-app-manifest-empresa.json` over the bot's app (it turns off Socket Mode and events); merge it by hand and test the bot afterwards. TRIED against real Slack (2026-11-05, on the bot's app "Pedro", Client ID in `slackApp.ts`): Slack only accepts the custom-scheme redirect URL AFTER PKCE is on (the Redirect URLs field says "Debes escribir una URL válida" before that; the manifest takes both together); the consent screen is read-only ("La información que Pedro puede ver") and carries the app's name and description, so people see "Pedro"; the token comes back EXPIRING (`expires_in` + refresh token), so the renewal in `SlackConnector.ensureFresh` is needed; the first sync after sign-in worked. Not yet seen with real data: a message arriving, and the renewal itself after the first expiry (hours later). The personal manifest `docs/slack-app-manifest.json` stays for the token-by-hand way. Not yet tried against real Slack (the `<@id>` mention search is the least certain part). Slack filters live in "Fuentes y filtros": "Canales de Slack", one row per channel with normal / urgente / ignorar (it writes `filters.mutedChannels` for ignored and `filters.importantChannels` for urgent, matched by "#name" with the same helper as people, `personRule.ts`), and "Personas de Slack" (listed with `users.list`), where each person is normal / urgent / ignored by adding their name to the SAME lists as "Remitentes prioritarios" / "Remitentes a ignorar" (shared with Gmail, matched by name: `src/shared/personRule.ts`).
- Distribution lists (Gmail): the user follows group addresses in "Fuentes y filtros" (`gmail.lists`: `address`, `name`, `urgent`), picked from the lists found in the last 90 days of mail (those that say their address in `List-Post`) or typed by hand. Their mail is NOT shown as individual emails (`sync.ts` skips it) but as one item per conversation in its own panel section "Listas de distribución", above "Próximos eventos" (`Signal.list`/`threadId`/`unread`; the id carries the last unread message, so a new reply comes back as news). Urgency works like individual mail (priority/ignored senders) plus `urgent` per list. Clicking opens `thread.html` (its own window, `windows/thread.ts`) with the messages as chat bubbles (who, time, who it answers via `In-Reply-To`). This REQUIRES the Gmail scope `gmail.readonly` (search `q` and message text are not allowed by `gmail.metadata`), so people who connected before must press "Volver a conectar". Still read-only: message text is read only in `getThread(..., withBody)` when a conversation is opened, never stored, never in a `Signal`, never sent to the AI; `tests/gmail.test.ts` guards it (one `format: 'full'`, no write verbs, no scope beyond `gmail.readonly`). Never tried against real Gmail yet: the `list:` / `to:` / `cc:` search and the `List-Post` discovery are the least certain parts. Mail sent to a Gmail contact group (expanded into individual recipients) has no list address and cannot be detected. What the chat shows of a message (`gmail/body.ts`): quoted earlier messages and the Google Groups footer (fixed text, ES/EN/PT) are removed; the signature (after a `-- ` line, or a last paragraph holding an `[image: …]` logo) is set apart and folded behind "···", never deleted; NEVER strip links: `<https://…>` is also how Gmail writes the link behind a text that was sent on purpose, so links become chips (`shared/richText.ts`) and stay reachable. Attachments show as small links (name + size, from the message parts; inline pictures with a Content-ID are skipped) that open the conversation in Gmail: files are not downloaded. Long messages fold ("Ver más"), the chat opens on the first unread message, and the window sits beside the panel (`windows/threadPlacement.ts`).
- Configuration by file (so a person's own Claude can configure the widget): the app keeps `%APPDATA%\widget\config.json` in step with the saved settings (non-secret only) and watches it; a valid edit is applied within seconds through `applySettingsPatch` (`src/main/settingsApply.ts`, the same path as the panel), an invalid one applies nothing and writes `config-error.txt`. The app also writes `CONFIGURAR.md` and `CLAUDE.md` (the guide, text in `src/shared/configGuide.ts`) into that folder, and Ajustes has a "Copiar instrucciones para Claude" button. `docs/CONFIGURAR.md` must equal `CONFIG_GUIDE` (a test checks it: update both when a setting is added). Tokens and accounts are never configurable by file or chat. Polling intervals are NOT configurable yet (constants in `accounts.ts`).
- Google: each person currently creates their own Cloud project. For 30 people a single company project (Internal consent screen if Google Workspace) is better.

## Gotchas
- In PowerShell, writing code with backticks or `${...}` inside double-quoted strings silently breaks template literals. Use the Edit tool.
- Dismissed items go to the trash (Ajustes > Papelera); `purge` empties them for good.
